# 电商运营数据分析助手

> 基于模拟订单的 Python 电商运营分析学习项目：严格校验数据，统一指标口径，生成可追溯的 Excel 表格和图表。
>
> **English:** A Python learning project for validating simulated ecommerce orders and producing operational metrics and visual Excel reports from CSV or XLSX files.

**项目定位：**面向电商运营助理、数据运营等实习岗位的作品展示，使用 Codex 辅助编程完成。所有样本均为虚构数据，没有真实客户信息、企业部署或实际经营业绩。当前已完成 CSV / Excel 导入、严格校验、指标计算和可视化报表；没有 AI 自动日报功能。

## 解决什么业务问题

一笔电商订单可能有多条商品明细。把明细条数当作订单数、重复累计每行的整单金额，或把未支付、取消、全额退款订单混在一起，会得到失真的运营结果。

本项目把“读取 → 字段确认 → 整份校验 → 指标计算 → 报表导出”连接起来，帮助使用者检查数据、解释口径，并从订单明细追溯汇总结果。它是对数据处理流程的练习，不是任意平台订单的通用分析系统。

## 已实现功能

| 环节 | 功能 |
| --- | --- |
| CSV 导入 | 读取 UTF-8（支持 BOM）中文 CSV，检查表头及行结构，保留原始行号 |
| Excel 导入 | 读取普通 .xlsx，明确选择一个工作表和单行表头；按显式别名映射字段，不做模糊猜测 |
| 映射确认 | 重复候选、额外列及金额粒度需要明确选择或确认；最终确认后才进行业务校验 |
| 严格校验 | 必需字段、空值、重复明细编号、日期、精确金额、数量、状态、退款及同一订单跨行一致性 |
| 指标计算 | 支付金额、退款、净销售额、去重订单数、两种客单价、商品净销量及商品交易金额 |
| 可视化 | 销售趋势、商品净销量前 10、退款分析；图表同时保留对应数据表 |
| Excel 导出 | 中文工作表、两位小数、冻结表头和筛选；记录输入来源，拒绝覆盖已有文件 |
| 失败保护 | 校验失败或用户取消时，不输出部分正式指标，不生成看似正常的正式报表 |

金额使用**整数分**累计，客单价和比率使用精确分数，只有展示时才四舍五入。CSV 和 Excel 共用既有校验器与指标逻辑，不各算一套。

## 快速开始（Windows）

已验证环境：**Windows、Python 3.13.2、openpyxl 3.1.5、et-xmlfile 2.0.0**。Excel 导出的安全发布目前仅支持 Windows；其他环境未承诺兼容。

### 1. 准备环境

在 VS Code 打开本项目文件夹，进入该目录的 PowerShell 终端。首次下载项目、且尚未创建 .venv 时执行：

~~~powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
~~~

先确认 python 指向需要使用的 Python 3.13 环境；本项目实际验证版本为 3.13.2。已有本项目 .venv 时直接复用，无需重复创建或安装。上述 pip 只作用于项目虚拟环境，不需要修改 PowerShell 执行策略。

requirements.txt 固定了两个依赖版本。纯 CSV 校验及 CSV 指标计算只用标准库；Excel 导入、导出和完整测试需要上述依赖。

### 2. 从自带模拟数据生成可视化报表

~~~powershell
.\.venv\Scripts\python.exe -B -X utf8 report_excel.py --visual
~~~

默认读取 data/sample_orders.csv，在项目 output/ 中生成带日期、时间和随机编号的新 .xlsx，并显示完整路径。

- 不带 --visual：保留基础三张工作表。
- 带 --visual：保留三张基础表，并增加三张分析表及三张图。
- 输出文件已存在时拒绝覆盖；可换新文件名，或省略 --output 让程序生成新名称。
- -B 避免生成 Python 缓存，-X utf8 帮助终端正确显示中文。

### 3. 其他常用命令

~~~powershell
# 只校验自带 CSV，不生成报表
.\.venv\Scripts\python.exe -B -X utf8 validate_orders.py

# 只在终端查看指标
.\.venv\Scripts\python.exe -B -X utf8 report_metrics.py

# 指定一个尚不存在的输出文件
.\.venv\Scripts\python.exe -B -X utf8 report_excel.py --visual --output "output\模拟运营分析.xlsx"

# 只检查 Excel；请将输入路径替换为自己准备的模拟订单文件
.\.venv\Scripts\python.exe -B -X utf8 inspect_excel.py "C:\模拟数据\订单.xlsx"

# Excel 导入、校验、指标计算及可视化导出
.\.venv\Scripts\python.exe -B -X utf8 report_excel.py "C:\模拟数据\订单.xlsx" --visual
~~~

Excel 流程依次选择工作表序号、表头行号，核实每列映射；对有歧义的金额字段确认其为“人民币元、商品明细分摊金额”，最后输入“确认”。额外列必须明确映射或忽略，缺失必需字段不能凭空补造。输入 q 或取消最终确认时不会继续计算或导出。

**导出的运营报表是汇总结果，不能当作订单输入模板。** Excel 输入也需提供同样的 14 个标准明细字段，详见[字段映射说明](docs/Excel订单导入与字段映射说明.md)。

## 报表展示内容

| 工作表 | 内容 |
| --- | --- |
| 运营总览 | 明细数、唯一订单数、支付、退款、净额、两种订单数及两种客单价 |
| 商品销量排行 | 完整商品编号、名称、类别、净成交件数及稳定排名 |
| 数据校验摘要 | 校验结果、计数、口径、生成时间及输入格式；Excel 另记工作表、表头行和快照 SHA256 |
| 销售趋势（--visual） | 按下单日期归组的支付、退款、净成交金额数据及折线图 |
| 商品销售分析（--visual） | 商品支付/退款/净件数及金额；按净成交件数排名，前 10 横向条形图 |
| 退款分析（--visual） | 退款总额、全额/部分退款订单、退款比率及按下单日期归组的退款折线图 |

图表引用同一工作簿中的实际计算结果；业务单元格写入 Python 已计算的静态值，不靠 Excel 公式重算指标。筛选商品表不会重新计算总览。

## 模拟数据与指标口径

data/sample_orders.csv 包含 **80 条商品明细、40 笔唯一订单、14 个字段、10 种虚构商品**。一行是一条订单商品明细，不是一笔订单，也不一定只有一件商品。

同一订单的时间、状态、渠道保持一致；discount_amount、payment_amount、refund_amount 是**该行分摊金额**，不是每行重复填写的整单金额。order_line_id 唯一，refund_quantity 明确记录退回件数，不根据退款金额猜测数量。

当前状态为：已支付、未支付、已取消、已全额退款、部分退款。只有已支付类状态（含后续全额或部分退款）进入支付指标。

| 指标 | 公式或规则 | 自带样本结果 |
| --- | --- | ---: |
| 支付金额 | 已支付类明细的实际支付金额之和 | 3724.57 元 |
| 已完成退款金额 | 已支付类明细的已完成退款金额之和 | 900.86 元 |
| 净销售额 | 支付金额 − 退款金额 | 2823.71 元 |
| 支付订单数 | 按 order_id 去重，包含全额退款订单 | 32 笔 |
| 净有效订单数 | 已支付且整单净金额大于零的唯一订单数 | 28 笔 |
| 支付客单价 | 支付金额 ÷ 支付订单数 | 116.39 元/笔 |
| 净客单价 | 净销售额 ÷ 净有效订单数 | 100.85 元/笔 |
| 净成交件数 | 已支付购买件数 − 明确退款件数 | 116 件 |
| 退款金额率 | 已完成退款金额 ÷ 支付金额 | 24.19% |
| 退款订单率 | 发生退款的唯一订单数 ÷ 支付订单数 | 25.00%（8 / 32） |

客单价或比率分母为零时显示“无法计算”，不伪装成零。商品按 product_id 汇总，净成交件数降序，并列按商品编号字符串升序；同名不同编号不会合并。只退差价、不退商品时扣金额而不扣件数。

**趋势的时间边界：**当前只有下单时间，没有支付发生时间或退款完成时间。图表表示“按下单日期归组的订单状态快照”，不是每日真实到账或每日退款流水；未出现的日期不补造零。净销售额不等于利润或会计收入，退款率也不是退款申请率。

完整定义及边界情况见[数据字段与统计口径](docs/数据字段与统计口径.md)、[指标计算说明](docs/指标计算说明.md)和[可视化运营分析说明](docs/可视化运营分析说明.md)。

## 已知限制

- 面向 Windows 本地学习场景，Excel 导出使用 Windows 无覆盖发布机制；未验证所有 Excel/WPS 版本及超大数据性能。
- 仅支持普通 .xlsx、一次一个明确选择的工作表和单行表头；不支持 .xls、加密文件、公式交易数据或合并单元格。未知状态不自动翻译，也不恢复已丢失的编号前导零。
- 日期检查覆盖整个工作簿；未选择页的不支持原生 ISO 日期也会被拒绝。带时区、非法尾随内容及不能无损接受的日期不得通过。
- 字段、类别、渠道及价格一致性规则较严格，不能直接保证兼容任意平台导出。当前仅应处理来源可信的模拟文件，未全面防御恶意 XML 或压缩包资源耗尽。
- Excel 有 15 位数值精度限制，超过现有安全范围时拒绝导出；金额累计精确不代表 Excel 可无限精度展示。
- 输入按只读流程处理，文本按文本写入以避免公式注入；导出有临时文件、回读及覆盖保护。强制终止或断电仍可能留下 .tmp，不能将其当作正式报表。
- 没有成本、运费、佣金、访客等数据，不能计算利润、ROI、转化率或复购率。没有真实平台接入、GUI、数据库、预测或 AI 日报。

## AI 辅助开发说明

本项目使用 **Codex 辅助编程**，用于需求拆解、代码实现、测试设计及审查；按小阶段验收和保留 Git 历史。展示重点是能解释业务规则、运行测试、核对结果和识别限制，不应把 AI 生成代码等同于已经掌握全部实现，也不把模拟数字写成真实运营成果。

# 电商运营数据分析助手 V1

## 当前状态

第三阶段：运营指标计算，2026-10-18。

**当前全部使用虚构模拟订单，不是真实客户或企业经营数据。已实现只读 CSV 读取、严格校验，以及校验通过后的四类运营指标计算。尚未实现图表或日报。**

本阶段没有安装第三方依赖、创建数据库、初始化 Git、上传 GitHub或连接付费 API。已结项的批量文件重命名工具不属于本项目。

## 这个项目解决什么问题

电商订单表经常把一笔订单拆成多行商品。如果直接数行数、把订单总金额在每行重复相加，或把未支付、取消、退款状态混在一起，运营数字就会出错。

本项目计划先把这些规则讲清楚，再让 Python 按确定的规则计算，最后生成便于检查的表格、图表与日报。计算结果必须可以追溯到原始明细。


- `sample_orders.csv`：80 条商品明细，40 个唯一订单，14 个字段，10 种虚构商品、4 个类别、4 个渠道。
- `数据字段与统计口径.md`：每列是什么意思、哪些订单计入指标、验收基准和边界情况。
- `开源项目调查.md`：四个真实仓库的源码、许可证、维护情况和复用决策，保留固定提交链接。
- `csv_reader.py`：只读检查编码、表头和 CSV 行结构，保留行号。
- `order_validator.py`：检查类型、金额、状态及跨行一致性，全部通过才返回数据。
- `validate_orders.py`：中文命令行入口；`test_csv_validation.py`：标准库自动测试。
- `读取与校验说明.md`：运行方法、报错示例、规则范围和本阶段验收记录。
- `metrics.py`：复用现有完整校验，再按订单和商品分别汇总；整数分累计，客单价保留精确分数。
- `report_metrics.py`：中文命令行指标报告，只在终端显示；`test_metrics.py`：指标和报告的隔离自动测试。
- `指标计算说明.md`：公式、实际验收结果、边界情况、运行和测试方法。

新增明细编号用于识别重复数据；新增退款件数用于区分商品数量减少与只退差价。没有姓名、电话、地址或客户编号，不支持识别客户或计算复购率。

## 如何查看和使用 CSV

1. 在 VS Code 中打开本项目文件夹，可查看 `data/sample_orders.csv`，也可按下节运行只读校验程序。
2. 第一行是字段名，之后的 80 行是数据；**一行是一条订单商品明细，不是一笔完整订单，也不一定只买一件商品**。
3. 相同 `order_id` 表示同一订单；`order_line_id` 唯一。订单时间、订单状态和渠道在同一订单各行保持一致。
4. 优惠、支付、退款都是该行的金额份额，可以按行相加得到订单金额，不是重复出现的整单总额。
5. 文件是 UTF-8（带 BOM，便于 Windows 软件识别中文）。程序使用 `utf-8-sig` 读取，并把金额转换为整数分进行精确校验。
6. 如果电脑已有 Excel，可通过“数据—从文本/CSV”导入，选择 UTF-8，并把订单和商品编号设为文本。不要为了本阶段另外安装软件。

币种为人民币，金额单位是元，全部保留两位小数。数量是售卖单位的件数，例如一套笔算一件商品。

模拟下单日期为 2026-10-01 至 2026-10-10。数据状态假定截至北京时间 2026-10-17 23:59:59。没有支付、退款发生时间，因此只能先分析这批订单的状态快照，不能冒充每日到账或每日退款流水。

## 指标为什么有用

| 指标 | 本项目 V1 的含义 | 可以帮助回答的问题 |
| --- | --- | --- |
| 已支付金额、退款、净销售额 | 3724.57 元、900.86 元、2823.71 元 | 这批订单曾支付多少，退款后保留多少商品交易金额？ |
| 有效订单数 | 净金额大于零的唯一已支付订单，共 28 笔 | 退款后仍有交易金额的订单有多少？ |
| 净客单价 | 2823.71 ÷ 28 = 100.85 元/笔 | 每笔净有效订单平均保留多少交易金额？ |
| 商品销量排行 | 默认按净成交件数排序，合计 116 件 | 扣除已明确退款的商品件数后，哪些商品成交件数更多？ |

这些是**固定模拟数据的验收答案，已由第三阶段程序及自动测试复核一致**。支付订单数为 32 笔，支付客单价为 116.39 元/笔；它们与净有效订单和净客单价是不同口径，不能混用。

净销售额不等于利润，也不是会计收入确认。当前没有成本、运费、平台佣金、曝光、点击或访客数据，不能计算利润、ROI、转化率，也不能凭数据断言某渠道或动作导致了增长。

## 运行 CSV 校验

在 VS Code 中打开本项目文件夹，在终端运行：

```powershell
python -B -X utf8 validate_orders.py
```

默认检查原始模拟文件，正常时显示“校验通过：读取 80 条商品明细”。也可以指定自己新建的模拟 CSV：

```powershell
python -B -X utf8 validate_orders.py "C:\你的临时目录\模拟订单.csv"
```

遇到错误时显示物理行号、字段和原因，返回失败状态；不修改文件，不补值、不去重，也不返回部分合格数据。表头或 CSV 结构错误需要先处理，再运行后续业务规则检查。

执行自动测试：

```powershell
python -B -X utf8 -m unittest -v test_csv_validation
```

不需要安装任何依赖。测试的异常数据位于每次新建并自动清理的临时目录中，原始模拟 CSV 只读。`-B` 避免生成 Python 缓存，`-X utf8` 帮助 Windows 终端正常显示中文。

第二阶段已完成独立数据复核、读取与校验模块和 43 项自动测试；具体说明见 `docs/读取与校验说明.md`。

## 运行运营指标计算

在本项目文件夹的 VS Code 终端运行：

```powershell
python -B -X utf8 report_metrics.py
```

也可在命令末尾加上自己新建的模拟 CSV 路径，例如 `python -B -X utf8 report_metrics.py "C:\你的临时目录\模拟订单.csv"`。默认路径相对于程序目录，不受当前终端位置影响；命令本身在其他目录启动时仍需写程序完整路径。

程序先调用原有读取和校验模块；任何数据错误都会显示行号、字段和原因，拒绝输出整份指标，不返回部分合格结果。运行不修改 CSV，也不保存报表文件。

- 支付、退款、净额分别为 **3724.57、900.86、2823.71 元**。
- 支付订单 **32 笔**，净有效订单 **28 笔**；商品明细 80 条不等于订单总数 40 笔。
- 支付客单价 **116.39 元/笔**，净客单价 **100.85 元/笔**；只在显示时四舍五入到两位。
- 商品按净成交件数降序、并列按商品编号字符串升序；合计 **116 件**。只退差价不扣件数，不根据退款金额推算件数。
- 没有支付订单时，金额和件数为零，客单价显示“无法计算（分母为零）”。空文件和仅表头文件仍报校验错误。

运行**全部原有和新增测试**：

```powershell
python -B -X utf8 -m unittest discover -v
```

在 Python 3.13.2 上实际通过 **76 项测试 = 原有 43 项 + 新增 33 项**。新增测试覆盖固定验收基准、多商品订单、退款、金额精度、零分母、稳定排序，以及错误数据不输出正式结果等情况。测试只读原始样本，其他输入均在新建的隔离临时目录中。

具体公式、完整商品排名和已知限制见 [指标计算说明](docs/指标计算说明.md)。本轮未更改原始模拟 CSV、第一阶段统计口径或既有校验源码与测试；未安装依赖或创建 Git 提交。

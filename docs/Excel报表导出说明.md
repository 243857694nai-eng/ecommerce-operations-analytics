# 第四阶段：Excel 运营报表导出

本轮以本地稳定提交 `778733785c73f36496ef74e1fecc9ac71c1282ce` 为基准，继续使用虚构模拟数据。实现日期：2026-10-18。本阶段不创建 Git 提交。

## 1. 解决什么问题

将已经校验通过、已经由 Python 算好的运营结果整理成可以查看和筛选的 Excel 报表。Excel 只负责展示，报表不包含重新计算业务指标的公式，修改原始 CSV 后需要重新导出。

导出入口 `export_excel(csv_path, output_path=None)` 首先调用现有 `metrics.calculate_metrics()`，读取和严格校验仍由原有模块完成，没有另写销售额、订单数、客单价或销量公式。

原始 `sample_orders.csv`、既有统计口径、读取与校验模块、指标模块及原有 76 项测试保持不变。本阶段没有开发 Excel 导入。

## 2. 环境和依赖

- Python：3.13.2，虚拟环境位于本项目 `.venv`。
- openpyxl：3.1.5；必要依赖 et-xmlfile：2.0.0。版本固定在 `requirements.txt`。
- 两个包仅位于 `.venv/Lib/site-packages`；`include-system-site-packages = false`；全局 Python 中仍没有 openpyxl。
- 虚拟环境自带 pip；未升级全局 pip，也未安装 pandas、绘图库、GUI 库或其他业务框架。
- 安装使用官方 `https://pypi.org/simple`、固定 openpyxl 版本及 wheel，未使用第三方镜像或源码构建。
- 已在该环境实际执行工作簿写入、回读、数值和异常测试，`pip check` 无依赖冲突。

当前环境已创建，无需再次安装。若将来需要重建，应先确认 `.venv` 不存在，再检查终端的 `python --version` 确实为 3.13.2，才执行以下步骤；版本不符时先选择正确解释器。不要覆盖已有环境，也不要使用全局 pip：

```powershell
python -B -X utf8 -m venv .venv
.\.venv\Scripts\python.exe -B -X utf8 -m pip --isolated install --index-url https://pypi.org/simple --only-binary=:all: --no-cache-dir -r requirements.txt
```

不需要激活虚拟环境，不需要管理员权限或修改 PowerShell 执行策略。

## 3. 运行方法

在 VS Code 打开本项目文件夹，在终端运行：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 report_excel.py
```

默认读取项目虚构样本，将新报表写入项目 `output` 目录。文件名带生成时间和随机编号，完整路径显示在终端。目录不存在时，在校验及内存回读通过后创建目录。

自定义模拟 CSV 和输出位置：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 report_excel.py "C:\你的临时目录\模拟订单.csv" --output "output\自定义模拟报表.xlsx"
```

显式指定的相对输出路径相对于当前终端目录；默认 `output` 和默认样本路径相对于程序目录。输出扩展名必须为 `.xlsx`。同名文件、目录或链接已存在时拒绝覆盖；请自行选择一个新名字。

成功返回退出码 0；校验或导出失败返回 1；缺少依赖或命令参数用法错误返回 2。缺少依赖时程序只提示使用项目虚拟环境，不会自动安装软件。

## 5. 精度和文本安全

1. 原有指标仍以整数分汇总，客单价仍是精确分数。导出仅调用已有 `format_money()` 作展示舍入，再写入 Excel 数值，不改动原始指标。
2. 零分母保留“无法计算（分母为零）”文本，不换成零或其他分母。
3. Excel 有效数值精度有限。本版本采取保守限制：金额包括两位小数在内，或件数／订单数超过 15 位数字时拒绝导出。指标命令仍可计算合法的大额整数分；不会为了 Excel 修改 CSV 或统计基准。
4. 保存前回读 XLSX，逐个检查值、数据类型、金额精度及关键数字格式。数值回读不一致时不生成正式文件。
5. 商品编号、名称、CSV 文件名等文本强制保存为字符串，包括以 `=`、`+`、`-`、`@` 开头的文字及 `#N/A` 等文本；不生成公式、超链接、外部链接或宏。
6. 超过单元格 32767 个 UTF-16 单元的文字拒绝导出，避免 openpyxl 静默截断。无法编码成合法 XLSX/XML 的文本也会报错，原始 CSV 保持不变。

这是对当前静态报表输出的保护，不等于对任意外部 Excel 文件的安全审计；本版本不导入用户提供的 XLSX。

## 6. 为什么失败不会变成正常报表

流程为：完整读取与校验 → 复用统计 → 内存生成 XLSX → 内存回读 → 输出目录中新建独占临时文件 → 完整写入并刷盘 → Windows 无覆盖改名发布。

- 校验、序列化或内存回读失败时，不创建正式报表；错误数据不会被静默删除后继续统计。
- 写入过程只操作本次新建的 `.excel_report_*.tmp`，正常异常和键盘中断都会尝试清理它。
- 发布使用 Windows `os.rename`，目标存在时会失败；不使用会覆盖目标的 `replace`。即使其他程序在先前检查后创建了目标，仍不能覆盖。
- 临时文件无法清理时会明确报告路径，不谎报成功；不会删除已有的目标文件。
- 不进行自动重试、覆盖、回滚或修复源数据。

突然断电或直接结束进程可能绕过清理，留下 `.tmp`；它不能作为正式报表使用。发布完成后、终端打印成功之前被打断，则可能已经存在完整报表；应先核对文件，避免误以为没有生成而重复操作。刷盘不等于对所有存储设备、网络盘及断电场景提供持久性保证。

当前发布流程明确只支持 Windows，临时文件位于目标目录，避免跨磁盘改名；没有为其他操作系统开发备用发布机制。网络共享、同步盘及各种磁盘故障的真实行为未全部验证。

## 9. 已知限制和下一步

不提供 GUI、Excel 导入、图表、AI 日报或数据库。没有使用真实客户数据或验证真实平台导出格式。

报表为静态结果；筛选商品表不会让运营总览自动重算。超大输入仍一次保存在内存中，生成和回读会增加内存开销，尚未做大文件压力测试。极长文本虽不会被静默截断，但受 Excel 行高限制，可能需要在编辑栏查看完整内容。

自动测试的 XLSX 写入和回读通过，不等于所有 Excel/WPS 版本的显示、打印或交互行为都已验证。等待验收后再讨论后续工作，不自动创建提交或进入下一阶段。

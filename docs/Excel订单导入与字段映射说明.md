# Excel 订单导入与字段映射（第五阶段 5A）

本功能用于学习和检查**虚构模拟订单**。它只读取一个明确选择的工作表，展示字段对应关系，经过确认后调用原有整份数据校验器。它不计算运营指标、不生成报表，也不修改 Excel 或写入中间 CSV。

## 1. 运行方法

在 VS Code 中打开本项目文件夹，用现有虚拟环境运行：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 inspect_excel.py "C:\你的临时目录\模拟订单.xlsx"
```

将引号里的路径替换为自己新建的模拟工作簿。不要使用客户订单练习。不需要激活环境、安装软件或修改 PowerShell 执行策略。已有 Python 3.13.2、openpyxl 3.1.5、et-xmlfile 2.0.0 可以满足本阶段需要，依赖文件没有变化。

若要查看命令帮助，可直接运行：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 inspect_excel.py --help
```

注意：`output` 中之前生成的三个工作表运营报表是汇总结果，不包含 14 个必需订单字段，**不能当作订单导入文件**。

## 2. 交互步骤

1. 程序只读一次文件，显示该份内存快照的 SHA256 和工作表列表。
2. 输入工作表序号。不会默认使用活动页，也不会合并多页。
3. 程序提示候选表头的原始行号及匹配数，用户输入真正的表头行号。候选提示不会替用户作决定。
4. 按列展示表头和候选字段。唯一候选可以按回车接受；也可以输入标准英文名称。未知额外列必须输入 `-` 明确忽略，或者明确映射到一个标准字段。
5. 重复表头必须明确输入选择；若两个不同源列都指向同一字段，必须保留其中一列、明确忽略另一列，否则停止。必需字段必须全部具备，不能通过确认补造退款件数或明细编号。
6. 含义模糊的金额字段、手动改映射到其他金额字段时，额外要求输入 `明细`：确认单位是人民币元，已经分摊到本行，并且业务含义正确。只有整单支付总额时不能这样确认。
7. 程序展示最终映射清单和忽略列。输入 `确认` 才会转换数据并开始现有校验。其他回答会取消；选择时可以输入 `q`，也可按 Ctrl+C 取消。
8. 整份校验通过后，只显示明细数、唯一订单编号数及快照提示。任何错误均拒绝整份输入，不输出部分合格结果。

退出码：`0` 为整份校验成功；`1` 为输入错误或程序异常；`2` 为取消、缺少依赖或参数用法错误。中断可能发生在校验期间，取消只代表没有返回成功结果。

程序不保存映射配置。下次启动仍需选择和确认。当前交互遇到冲突会停止，需要核实后重新运行，不会自动修复原文件。

## 3. 标准字段与明确别名

标准英文名称可以直接作为表头，只对表头去除首尾空白，不忽略大小写、不做近似匹配。**数据单元格不去空白、不翻译状态、不补值。**

| 标准字段 | 可以自动提出的中文候选 | 数据要求 |
| --- | --- | --- |
| order_id | 订单编号、订单号 | 非空文本，按订单重复出现是正常情况 |
| order_line_id | 订单明细编号、明细编号 | 非空文本，整份数据唯一，不自动生成 |
| order_time | 下单时间 | 完整日期和时间，按既有北京时间规则解释 |
| product_id | 商品编号 | 文本；不凭商品名称合并 |
| product_name | 商品名称 | 非空文本 |
| category | 商品类别 | 既有四类，不自动扩充 |
| quantity | 购买数量 | 合法正整数 |
| unit_price | 商品单价（元） | 优惠前单价，人民币元 |
| discount_amount | 明细优惠金额（元） | 分摊到本行的优惠 |
| payment_amount | 明细支付金额（元） | 分摊到本行的历史支付，退款前 |
| order_status | 订单状态 | 已支付、未支付、已取消、已全额退款、部分退款 |
| refund_amount | 明细退款金额（元） | 分摊到本行的累计已完成退款 |
| refund_quantity | 退款件数 | 明确的非负整数；空白不等于零 |
| channel | 下单渠道 | 既有四种渠道，不自动扩充 |

`实付金额`、`订单优惠`、`退款金额`仅是**需要额外核实的候选**。例如“退款金额”可能指整单总额、申请中退款或已完成退款，仅靠名字不能确定。其他表头可以由用户手动指定；程序不能证明用户对含义的确认是否真实正确。

订单级信息、商品级信息和退款关系仍完全采用 `数据字段与统计口径.md` 和 `order_validator.py` 的规则。类别、渠道、同商品单价一致性等限制也仍然存在；这不是任意电商平台通用导入器。

## 4. 类型转换与错误定位

- **编号和其他文本**：编号必须在源文件里以文本存储。`00001`、超过 15 位的文本编号原样保留；数字单元格即使显示格式是 `000000`，也不猜测前导零。已经被 Excel 截断的编号无法恢复。
- **金额**：文本金额继续要求两位小数，如 `19.90`；文本 `19.9` 不会被悄悄改成合格数据。原生数值 `19.9` 可以无损补足为 `19.90`。从工作簿内部 XML 保留数值字面量，用 Decimal 检查，避免先转 float 丢掉多余小数。超过两位的非零小数、超出保守的 15 位数值范围明确拒绝，不进行四舍五入；大额精确文本仍交给原校验器处理。
- **数量**：原生数值只有整数才可转换；布尔值、1.5、负数、非法整数文本等不合格。退款件数不从退款金额推算。
- **时间**：标准文本为 `YYYY-MM-DD HH:MM:SS`。支持具有日期与时间格式的原生 datetime，按原规则解释为北京时间；支持 Excel 1900/1904 日期系统。日期不含时间、仅时间、无日期格式的裸序列号、可见小数秒等拒绝，不擅自补造或截断。1900 日期系统虚构的 2 月 29 日明确拒绝。
- **原生 ISO 日期保护**：读取同一份文件快照中的原始 XML，在 openpyxl 解析前检查所有 `t="d"` 日期单元格全文。订单时间采用 `YYYY-MM-DDTHH:MM:SS`，允许只包含零的小数秒（如 `.000`，不改变时间值）；拒绝 `Z`、时区偏移、非零小数秒、非法尾随字符及不存在的日期。单独的 ISO 日期或时间可通过格式预检查，但映射为订单时间时仍被原有转换规则拒绝。预检查发现错误会直接停止读取并显示工作表、行列位置，不会等到丢失原文后只检查 datetime。检查覆盖整个工作簿，包括未选择的页；不静默放过无法可靠解析的原生日期。
- **公式与错误值**：读取时使用 `data_only=False`，拒绝公式和 Excel 错误单元格，即使存在看似正确的公式缓存，或者该列已明确忽略。以 `=` 开头但实际存为普通文本的内容不是公式，仍由现有字段规则校验。
- **结构**：所选表出现合并单元格、隐藏列或表头及之后的隐藏行时停止。工作表本身被隐藏也拒绝。表头不能为空；格式扩展出来的空白行、空白表头也不会静默丢掉。合计行不自动删除，缺失或不符合标准的数据会报错。

数据错误示例：`工作表 '模拟订单' 第 3 行 J 列：[payment_amount] 实际支付必须等于数量乘单价减去本行优惠。`

行号保留 Excel 原始位置，包括表头前的说明行。必需字段缺失等表头错误定位到工作表和表头行，能定位的列一并显示。文件损坏、加密或 XML 无法解析时，可能只能定位到文件，程序不会编造单元格位置。

## 5. 如何复用已有模块

```text
Excel 字节快照
  → 选择单个工作表和单行表头
  → field_mapping 的逐列映射与明确确认
  → excel_reader 转换为 RawCsvRow（值仍是标准文本，携带原始行号）
  → 原有 validate_rows()
  → 全部通过才返回 OrderLine 和校验摘要
```

没有直接构造 OrderLine 绕过规则，没有复制退款或订单校验公式，没有改动 CSV 路径、metrics.py 或报表导出流程。模块导入不会读取订单、调用校验器或提示输入。

映射绑定到 SHA256、工作表、表头行和表头列表。校验转换前再次检查映射完整性。预览后磁盘文件即使被替换，本轮仍校验原内存快照，**不表示替换后的文件也通过了校验**；想检查最新文件，必须重新启动并确认。当前没有文件锁或跨进程并发保障。

## 7. 限制和未验证范围

- 仅普通 `.xlsx`、单个明确选择的工作表、单行表头；不支持宏、旧版 `.xls`、加密文件、合并表头、多页拼接或自动平台适配。加密识别测试使用模拟容器签名，尚未逐一验证真实密码加密文件和所有办公软件版本。
- 一次读取并解析整个工作簿，数值字面量保留还增加一次 XML 读取；尚未做超大文件、极端单元格维度或压缩包资源耗尽测试。
- 没有新增安全解析依赖；不能宣称防御所有恶意 Excel/XML/压缩包。当前只适合自己创建、来源可信的模拟文件，不应据此直接接入不可信外部订单。
- Excel 自身可能已经丢失编号、金额或时间精度；程序无法恢复。openpyxl 原生日期解析具有毫秒分辨率，无法据此保证识别所有亚毫秒时间精度损失。要求精确整秒时，应从可靠来源提供规范时间文本；业务时区仍由用户确认。
- 未映射列不进入 RawCsvRow 或业务校验器，也不打印整行，但加载工作簿时仍会经过内存，并非敏感信息脱敏工具。程序不在磁盘保存导入记录或日志。
- 交互确认用于防止误操作，不是隔离恶意 Python 代码的权限系统。整份数据通过只表示符合 V1 已定义规则，不能证明交易真实或用户选定的业务粒度正确。
- 5B 已接入统一输入、指标和报表流程，见 [CSV 与 Excel 完整流程说明](CSV与Excel完整流程说明.md)。单独运行本说明的 `inspect_excel.py` 仍只做检查，没有 GUI、映射持久化和自动补值。

本阶段沿用之前调查结论：只使用已有 openpyxl 和 Python 标准库，没有复制 django-import-export、Tablib 或 Pyexcel 代码，也没有引入框架及新依赖。5B 复用本交互与校验流程，独立检查命令的用途保持不变。

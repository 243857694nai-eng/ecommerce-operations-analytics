# 5C 可视化运营分析说明

日期：2026-10-19。用途：电商运营助理求职的学习项目展示。
本项目只使用虚构模拟订单，不代表真实企业经营数据或个人运营业绩。

## 1. 怎样生成

在 VS Code 打开项目文件夹，在该目录的终端运行：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 report_excel.py --visual
```

默认读取 `data/sample_orders.csv`，在 `output` 生成日期、时间和随机编号组成的新 `.xlsx`，终端显示完整路径。没有安装新依赖，不需要激活虚拟环境。不带 `--visual` 保持原来的三工作表格式。

自建模拟 Excel 输入：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 report_excel.py "C:\你的临时目录\模拟订单.xlsx" --visual
```

仍然需要选择工作表和表头、逐列核实映射、确认金额粒度，最后输入 `确认`。取消或整份校验失败不生成报表。`inspect_excel.py` 仍只检查订单，不生成图表。

也可以指定一个尚不存在的输出文件：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 report_excel.py --visual --output "output\模拟分析展示.xlsx"
```

同名文件存在时拒绝覆盖，换新名称或省略 `--output`。已有汇总报表不能作为订单输入模板。

## 2. 六张工作表及图表

原有“运营总览”“商品销量排行”“数据校验摘要”保留指标、排序及来源记录。可视化模式另外追加：

| 工作表 | 数据表 | 图表与位置 |
| --- | --- | --- |
| 销售趋势 | 第4行为表头；第5行起，日期、支付、退款和净成交金额（元） | F4：三条金额折线，引用表内实际数值 |
| 商品销售分析 | 第4行为表头；全部已支付商品的排名、编号、名称、类别、支付/退款/净件数、支付/退款/净额 | M4：净成交件数前10的横向条形图；向右滚动可完整查看 |
| 退款分析 | 第4行起退款总额、支付与退款订单数、全额/部分退款计数和两个比率；第15行起按下单日期归组的数据表 | F15：累计退款金额按下单日期归组的折线；向下滚动查看 |

图表标题明确标注模拟数据和单位。新分析表默认90%查看比例，冻结前4行；金额两位小数、日期 `yyyy-mm-dd`。商品图用“名称 / 编号”区分同名不同商品。净销量相同仍按商品编号字符串升序，前10并列时也只取前10；完整表不截断。

销售和退款图的日期轴保留真实日期间隔，只展示输入中出现的下单日期，不替缺失日期补造零。折线只用于连接已有观测点，不是对缺失日期数值的推断。单日有实际标记点，不伪造第二天。

## 3. 时间和金额口径

原始模型只有 `order_time`（北京时间下单时间），没有支付发生时间或退款完成时间。因此：

- 某日期的支付金额：该日下单、当前为已支付类状态的明细历史支付额合计，包含后来全额或部分退款的订单。
- 某日期的退款金额：上述订单截至输入快照的累计已完成退款合计，并非该日期实际发生的退款。
- 某日期的净成交金额：该日订单支付金额减累计退款，沿用既有净销售额定义，不代表利润。
- 未支付和取消订单不贡献成交金额、退款或销量。如果某日期只有这些订单，该日期金额为零；并非整份空输入。

不能据此回答“10月5日实际退了多少钱”“今天的到账金额是多少”，也不能计算退款处理时效。需要支付/退款事件日期等新字段才能做资金发生日分析，本轮没有补造这些数据。

商品销售金额同时列出支付、退款和退款后净额；净销量只扣明确退款件数。只退差价且退款件数为零时扣金额、不扣销量。不使用退款金额推算退货数量，不把同名不同编号合并。

## 4. 退款订单与比率

| 指标 | 分子/计算 | 分母及限制 |
| --- | --- | --- |
| 退款订单数 | 当前状态为已全额退款或部分退款的唯一订单数 | 一单多行只计1笔；现有校验保证相应整单退款金额大于0 |
| 全额/部分退款订单数 | 分别按原有整单状态去重 | 部分退款包括只退差价；不是按某一行是否全退判断整单 |
| 退款金额率 | 累计已完成退款金额 | 支付金额，包括后来全额退款订单；不是退款申请率 |
| 退款订单率 | 发生退款的唯一订单数 | 已支付类唯一订单数，包括全额退款订单；不是商品退货件数率 |

比率在模型中使用精确 `Fraction`；写入展示单元格时才四舍五入到0.01%，保留百分比数值格式。分母为零显示“无法计算（分母为零）”，不伪装成0%。无退款但支付分母大于零时才显示0.00%。

## 6. 实现与安全边界

数据流仍为 `order_loader → 原读取/映射 → validate_rows → calculate_metrics → excel_report`。只在整份校验通过后的原循环中增加按日归组及退款订单去重，商品金额和件数直接使用已有 `ProductMetrics`，没有复制校验或修改统计公式，也不重新读取 Excel。

`export_excel(..., visual=True)` 先创建原三张表，再追加分析表。沿用内存序列化回读、同目录临时文件、刷盘和 Windows 无覆盖发布。保存前增加图表 XML 回读比较，检查图表数量、系列、标题、轴设置和引用是否丢失或改变。业务单元格只写静态已计算值；图表引用是本工作簿内部的数据引用，不是新增业务计算公式。文本仍强制以文本保存。

这些回读检查不能代替办公软件的实际显示检查，也不保证抵御所有恶意工作簿。正式输入、既有报表、原始模拟 CSV 都不会被覆盖。硬退出或断电仍可能留下 `.tmp`；暂存文件不是正式结果。当前安全发布仅支持 Windows。

Excel 的15位数值精度保护不变。金额继续按整数分累计，未提前舍入；比率仅展示时舍入。新增按日统计需要额外保存日期和订单集合，大数据有额外内存开销，本轮未做超大数据性能基准。

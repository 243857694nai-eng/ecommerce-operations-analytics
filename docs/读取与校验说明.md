# CSV 读取与严格校验说明

阶段：第二阶段；日期：2026-10-18。

仅适用于当前 V1 字段和业务规则。程序不修改 CSV，不生成分析表、图表或日报，也不连接数据库或 API。

## 1. 开发前的独立复核

先读取 README、字段与统计口径、开源调查和原始 CSV，再用一次性只读检查独立核对原始数据，没有调用本轮新模块来证明它们自己正确。

- 原始数据：80 条商品明细，14 个字段，40 个唯一订单，五种状态均符合第一阶段记录。
- 历史支付 3724.57 元，已完成退款 900.86 元，净额 2823.71 元。
- 支付订单 32 笔，净有效订单 28 笔，支付客单价 116.39 元、净客单价 100.85 元。
- 支付件数 142、退款件数 26、净件数 116；商品排行与第一阶段固定答案逐项一致。
- 未发现空值、重复明细、金额或状态矛盾、退款越界或同订单字段不一致。
- 原始 CSV SHA256：`9179FFCAFA6179D66EC0EAD583042D32B56D282624E6DAD734B083E7D18F0E5C`。

以上是本轮开发前的复核记录，不是新校验程序的运营指标输出。第一阶段的 CSV、统计口径和开源调查文件保持原样。

## 2. 为什么只使用标准库

80 条样本不需要安装 pandas 或 Web 框架。延续第一阶段的开源调查结论，本轮没有复制候选项目代码；主要使用：

- `csv`：处理逗号、引号和 CSV 结构。
- `pathlib`、`io`：只读打开文件和处理文本。
- `re`、`datetime`：检查类型格式和真实日历日期。
- `dataclasses`：把通过检查的数据表示成字段明确的对象。
- `unittest`：自动测试。

金额转换成整数“分”，例如 `19.90` 保存成 `1990`，使用整数比较与加总，避免二进制浮点和固定 Decimal 运算精度引起误差。

## 3. 文件职责和调用顺序

1. `csv_reader.read_csv(path)`：按 UTF-8 读取（兼容带 BOM 和不带 BOM），检查表头、重复列、空白记录、列数和引号结构，记录物理起止行号。
2. `order_validator.validate_rows(rows)`：检查必填值、类型、行金额关系、整单状态和跨行一致性。
3. `order_validator.load_and_validate(path)`：把前两步串起来，只有整份数据通过才返回 `OrderLine` 列表。
4. `validate_orders.py`：把成功或错误信息显示为中文，并返回退出码。

模块被导入时不会自动读取样本、运行主程序或写文件。通过校验的对象中金额字段以 `_cents` 结尾，例如 `payment_amount_cents`，表示单位为分，不能误当作元。

只为检查“部分退款”是否真实介于零退款和全额退款之间，模块会内部加总该订单的支付与退款。这是合法性检查，不是对外生成运营指标。

## 4. 运行方法

在 VS Code 中打开本项目文件夹，打开终端运行：

```powershell
python -B -X utf8 validate_orders.py
```

预期输出：

```text
校验通过：读取 80 条商品明细。
原始 CSV 未修改；当前阶段不计算运营指标。
```

默认样本路径以程序所在目录为准，从其他工作目录启动也不会误读另一个同名文件。

指定其他新建的模拟文件：

```powershell
python -B -X utf8 validate_orders.py "C:\你的临时目录\模拟订单.csv"
```

无须 `pip install`。程序不会生成修复后的文件，也不会覆盖输入。

## 5. 校验规则

### CSV 结构

- 必须包含既定的 14 个字段，每列只能出现一次；字段顺序可以调整，未知字段会报错，不能默默忽略。
- UTF-8 解码失败不尝试猜测其他编码，也不把乱码替换成看起来正常的文本。
- 空文件、只有表头、额外或缺少列、空白记录、引号结构错误都不算通过。
- 每个必需值都不可为空；前后空白或控制字符会明确报错，不自动清理。当前 V1 不接受字段中的换行或制表符，但正常的带引号逗号字段可读。

### 类型和行级关系

- 购买数量为正整数，退款件数为非负整数，不接受小数、指数、符号或非规范前导零。
- 金额为非负十进制数且恰有两位小数，例如 `0.00`、`19.90`；不接受负数、千分位、科学计数、NaN 或 Infinity。
- 单价必须大于零；优惠不超过数量乘单价；退款金额不超过行支付；退款件数不超过购买数量。
- 有退款商品件数时必须有退款金额；只退差价可以有退款金额但退款件数为零，不会据金额猜件数。
- 时间严格使用 `YYYY-MM-DD HH:MM:SS`，同时检查闰年、天数、时分秒；读取后统一标记为北京时间 UTC+08:00。

### 状态和跨行关系

- 状态、类别和渠道按口径文档的 V1 枚举检查，未知取值不自动映射。
- 已支付、全额退款、部分退款：本行支付必须大于零且等于数量乘单价减优惠。
- 未支付与支付前取消：支付、退款和退款件数都为零。
- 已支付未退款状态：不得出现退款；当前 V1 全额退款明细要求全额金额和全部商品件数均退款。
- 部分退款按整单判断：总退款必须大于零、小于总支付；其中一行可以全额退款，另一些行没有退款。
- 明细编号全文件唯一。重复时指出当前行和首次出现行，不自动去重；同一订单、同一商品可以合法出现不同明细编号。
- 同一订单的时间、状态和渠道一致；同一商品编号的名称、类别及当前 V1 单价一致，并指出首次出现行。
- 对已经有错误、资料不完整的订单，不再基于不完整行集合猜测整单退款状态；整份数据仍判为失败。

样本中的“80 行、40 单、数量 1–4、SIM 编号和 2026-10-01 至 10-10”是样本特征，**没有写死为通用校验限制**。其他正整数数量、合法编号和日期可以通过。本程序只检查日期格式与日历合法性，不自动判断是否早于某个业务快照。

## 6. 如何理解报错

例如临时文件第 3 行退款金额超过支付时，会显示类似：

```text
校验未通过，共发现 1 个问题：
- 第 3 行 [refund_amount]：退款金额超过本行实际支付金额。
未返回部分数据，未修改 CSV，也未填补或删除任何记录。
```

一行可能违反多条规则，因此具体问题数可能多于一。结构检查不通过时，先修正表头或记录边界，再运行业务检查；遇到无法可靠继续解析的引号错误，停止读取，不猜测后面的行。

行号含表头，第一条数据通常是第 2 行。CSV 引号中的换行会造成一条记录横跨多条物理行，错误会显示起止行号。文件不存在、无法读取或只有表头等问题会标为文件级错误，不编造不存在的数据行号。

退出码 `0` 表示全部通过；`1` 表示文件或数据校验失败；命令行参数用法错误由标准参数解析器返回 `2`。程序不替用户决定如何修复原始数据。

## 7. 自动测试

```powershell
python -B -X utf8 -m unittest -v test_csv_validation
```

共 43 个测试方法，包含多组参数化异常输入。覆盖中文编码、表头、缺失值、重复明细、列数与引号、物理行号、日期、金额、数量、状态、同订单与同商品一致性、部分退款和只退差价、命令行及导入无副作用。

原始样本只读；异常数据在每次新建的 `csv_validation_` 临时目录中，测试结束清理这些新目录。测试检查通过与拒绝过程中输入字节保持不变；大额金额测试验证精确整数分，不把正常大额数据四舍五入后误判。

## 8. 当前限制与下一步

当前规则针对本项目 V1 模板，不等于所有平台的通用清洗工具。例如真实商品会调价、平台可能有新渠道或付款后取消，当前严格规则可能拒绝这些业务合法但尚未定义的情况，届时应先确认口径和字段映射。

程序一次把 CSV 读入内存，面向小规模本地文件；没有进行大文件性能测试。CSV 解析器自身的字段长度上限和 Python 整数解析限制会转换成错误提示，不会静默截断。它不能仅凭一份 CSV 验证交易是否真实，也不能核对未提供的整单总额或外部退款流水。

尚无正式指标、GUI、Excel、图表或日报。下一步在你验收后，再以全部通过校验的数据为输入开发指标模块，并与第一阶段静态验收答案对照。
